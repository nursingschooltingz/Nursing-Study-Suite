# v17.3 release verification

Date: 2026-09-23. Release: v17.3. Prepared from the v17.2 tree at commit `255f30c`. At the time this record was written the changes were in the working tree, not yet committed or published; the README download link for v17.3 becomes valid once the release asset below is uploaded.

This release implements steps 1–3 and 5–10 of the [2026-09-23 production review](production-review-2026-09-23.md) plan, withdraws step 4 (finding 5) and finding 16, and leaves finding 7's retention in place by design:

- **Finding 1 (High):** the settings drawer's entry-focus effect re-ran on every `App` render and stole focus into the API key field (v17.0 regression). It is mount-only, reads the close callback through a ref, and `App.closeSettings` is memoized.
- **Finding 3:** the Knowledge Base study view and the four Priority tier sections memoize their sanitized HTML; `activeTool` left the config context (the drawer receives it as a prop); the six tools are `React.memo` components.
- **Finding 2:** persistence metadata carries `meta.digest` (cyrb53, two seeds) instead of `meta.bytes`, a second serialized copy of the KB. Legacy records verify by `bytes` and are rewritten in digest form on their next save. A tombstone carries the digest of the null snapshot.
- **Finding 6:** sanitized study links open in a new tab with `rel="noopener noreferrer"`.
- **Finding 4:** the Knowledge Base build gains an opt-in second lane (`kbRunLanes`, `kbCompareOrder`) with chunk-ordered assembly. Default off. Priority, NCLEX and Anki pipelines are unchanged.
- **Findings 8 and 9:** the Flash and Pro model names, the manual Flash/Pro switch and both manual thinking levels persist under `latte_model_settings_v1`; `loadModelSettings` validates each field and falls back per field to `MODEL_SETTINGS_DEFAULTS`. A saved per-tool profile row is used only when it is a complete, recognized row; unknown tool ids are dropped and the `casesAudit` → `itemAudit` migration still applies.
- **Finding 10:** recovery archives are pruned to the newest five (`KB_RECOVERY_ARCHIVES`) in IndexedDB and in the browser fallback. The fresh archive is written first; a pruning failure never removes it.
- **Finding 13:** the Anki numeric tokenizer's two regexes are module-level (`ANKI_UNUSUAL_RE`, `ANKI_TOKEN_RE`) and `ankiFactTokens` caches a fact's tokens per snapshot fact object and field, so a fact linked by many notes is tokenized once per snapshot.
- **Finding 14:** card identity conflicts are keyed by file identity (`cardFileId`) instead of basename.
- **Finding 15:** `extractJSON` tries every fenced block and retries a brace scan from the first line that begins with a brace, but only after the previous order has failed, so every previously accepted response yields the same value and an unrecoverable input reports its original failure.
- **Finding 17:** `AnkiGenerator` no longer writes refs during render; a memoized value serves render-time readers and an effect syncs the refs used by handlers and in-flight checks. The batch-diagnostics JSON is built only while its details element is open.
- **Finding 11:** one `useCappedLog` hook replaces six copies of the capped log setter, and the NCLEX grounding-adapter text exists once (`NG_GROUNDING_ADAPTER`) and feeds both packet forms byte-identically. Deliberately not consolidated: the Anki and case decimal normalizers and the two unit vocabularies (the harness extracts those sections independently; an assertion keeps the normalizers byte-identical and both vocabularies on one denominator grammar), the three HTML escapers (boot-script isolation and Anki CSV/HTML export bytes), the abortable-promise helpers and the three focus-block builders (different prompt wording).
- **Finding 12:** eleven unused stylesheet rules (1,747 bytes) are removed. The 483 inline styles are left for a presentation pass.
- **Finding 19:** React 18.2.0 → 18.3.1 with both SRI pins re-hashed (19 dropped the UMD builds this single file depends on). Babel standalone 7.29.9 compiles the suite in the same time as 7.23.9 and was not adopted. The PDF.js ESM migration is written up as its own plan in [pdfjs-esm-migration-plan-2026-09-23.md](pdfjs-esm-migration-plan-2026-09-23.md); nothing there is implemented.
- **Finding 5 withdrawn:** with the boot timer cut to 1 second and a 2.9 s compile, the app mounted with no error. The Babel compile runs synchronously inside DOMContentLoaded, so a pending timer cannot fire during it. No change was made.
- **Finding 16 withdrawn:** the nested-PPTX-run rejection is the v16.7 amplification guard, nested `a:t` never occurs in well-formed DrawingML, and a real-DOM browser test pins it. No change was made.
- **Finding 7:** raw model responses are intentional exportable evidence; moving them out of React state would retain the same memory. Only the per-render diagnostics stringify was removed.

The canonical filename, release comment, `suiteVersion()`, case-builder provenance label, README download link, maintainer documentation, changelog, prompt-library labels and version assertions agree on v17.3. No generation prompt bytes, model profiles, warning tiers or export formats change. One dependency changes (React 18.3.1) and one storage key is added (`latte_model_settings_v1`).

## Executed checks

- `node verify-repo.js` on the final bytes: **3,360 assertions passed, zero failed** (3,281 at v17.2, plus 10 in `tools/settings-focus-tests.js`, 6 in `tools/render-memo-tests.js`, 13 in `tools/persistence-digest-tests.js`, 9 in `tools/kb-lanes-tests.js`, 13 in `tools/settings-persistence-tests.js`, 24 in `tools/review-low-findings-tests.js`, 3 lane assertions in `tools/anki-integrity-source-regression.js` and 1 link assertion in `tools/remediation-resource-tests.js`); one canonical LF-only HTML; filename/release-comment agreement; all eleven unchanged frozen prompt hashes; prompt documentation; full JSX Babel transformation.
- `tools/settings-focus-tests.js` run standalone against the v17.2 bytes from `git show HEAD`: **6 of 10 assertions fail**, including both behavioral re-render checks, so the module is coupled to the fix rather than to its inputs.
- The lane assertions build a two-page synthetic source once sequentially and once with two lanes whose second chunk deliberately finishes first; both runs publish the same Knowledge Base with facts numbered in chunk order, and diagnostics keep chunk order. The synthetic runner reports the expected overlap (8 jobs × 15 ms: 140 ms on one lane, 62 ms on two). The live wall-clock gain was not measured because no Gemini calls were authorized.
- `tools/settings-persistence-tests.js` runs the shipped `loadModelSettings` and the shipped profile initializer against fake storage: empty, malformed and throwing storage yield the defaults; a valid snapshot is restored field by field; a mixed snapshot (bad model name, non-string model, non-boolean switch, unknown level) falls back field by field; a profile row with an unrecognized level or a non-object row falls back to its recommended row while a complete recognized row is kept exactly.
- `tools/review-low-findings-tests.js` runs the shipped `extractJSON`, `kbArchiveRecovery` (against a fake IndexedDB and against the localStorage fallback) and the Anki tokenizer: old extraction order preserved and new fallbacks reached only after it fails; archives pruned to the newest five with the fresh archive surviving a pruning failure; tokens cached per fact object and field, re-tokenized when the text changes, frozen snapshot facts cached without mutation, and the numeric audit still detecting a match and a mismatch through the cache. Source contracts pin the file-identity conflict keys, the single adapter constant, the byte-identical decimal normalizers, the shared denominator grammar, the removed stylesheet rules, the React 18.3.1 pins and the effect-synced Anki refs.
- `node tools/visual-browser-tests.js` (external Playwright 1.62.1, headless Chrome) on the final bytes: **passed at 360, 768, 1024 and 1440 px, 78 checks**, including typing into the Flash model field at every width, a rendered Priority link carrying `target="_blank"` and `rel="noopener noreferrer"`, and a populated-workspace check that typing the API key and switching tools makes zero real `marked.parse` calls. - `node tools/anki-generation-quality-browser-tests.js` (25 checks), `node tools/anki-source-review-browser-tests.js` and `node tools/production-recovery-browser-tests.js` passed. ## Limits

No live Gemini calls were made. No private course material was used; the browser checks used synthetic fixtures or a synthetic Knowledge Base. The browser checks ran on a desktop; mobile devices were not tested. Older builds cannot read digest-only persistence records; export the Knowledge Base before downgrading, as the v15.18 notes already advise. The two-lane build's effect on real provider latency and per-minute quota is unmeasured. React 18.3.1 was exercised only through the harness transform, the Playwright runners and the loopback boot above; no user workflow was replayed end to end on it. Still open from the review: the presentation-only inline-style migration (finding 12, second half), the harness's exact assertion total (finding 18) and the PDF.js ESM migration (finding 19, planned separately).
