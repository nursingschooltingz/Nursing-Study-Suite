# Anki v16.4 implementation and verification

Date: 2026-09-13. Scope: the approved audit-reference, recovery and source-accounting improvements following four supplied v16.3 tests, followed by explicit authorization to commit, push and publish v16.4 as the latest release. The canonical file is `Nursing-Study-Suite v16.4.html`; the identical release attachment is `Nursing-Study-Suite.v16.4.html`.

## Implemented behavior

- New audit packets replace internal note UUIDs with exact packet-local handles and expose numbered source tokens. Responses cite inclusive token ranges; the app restores exact captured source bytes and original note identities. Unknown handles, invalid ranges and nonexistent cloze indices remain errors. No fuzzy ID, broad case-folding or inferred-cloze repairs were added. Reports retain note-handle maps and positional source references.
- The dynamic audit builder asks for a source-first inventory before matching existing cards. Every source token must belong to exactly one target or explained context range, and every target range needs a coverage record. Meaningful list members are separate targets. Whole-source propositions, including actor, action, certainty, frequency, conditions and numerical roles, must be compared with revealed Text and Extra. Exact addresses and complete accounting do not prove the model made the right semantic choices. [Exact dynamic prompt diff](../history/ANKI-v16.4-audit-builder.diff).
- Hidden references have explicit existing cloze indices; contextual Text/Extra references use separate roles. A valid tested reference survives an additional contextual mention. Visible-only and Extra-only records still enter advisory review. Identical wording at different source addresses produces separate receipt items and review decisions.
- The strict legacy validator remains available for historical regressions. The new decoder independently validates findings, fact inventories and note-field receipts, preserving valid records while retaining unresolved obligations. Invalid findings cannot satisfy receipt dependencies. Duplicate records, invalid IDs and missing required records cannot be silently counted as checked. Explicit retry merges only records from the exact captured packet, retaining earlier valid records and every raw attempt. Transport failure stops the session; changes to notes, tier or source invalidate the capture.
- Report schema 4 distinguishes the count of complete groups from groups with retained records. An attempt's `accepted` field describes that raw response; `groupComplete` describes the accumulated group. Complementary partial attempts can complete required work without falsely declaring either response fully valid. Both the newly accepted and cumulative retained record counts are exported, alongside unresolved issues, failure/session history and review decisions.
- Whole-deck review searches reliable same-condition source mappings across captured chunks and tiers for literal hidden-answer candidates. At most five links are shown, with total counts and selection/tier status. Candidates cannot clear a finding or authorize deletion. Additional advisories identify broad tested-list spans with unmatched segments and facts classified entirely as context. Mixed inventories remain inspectable without a queue warning for every connective word.
- Actual wire payload size, including source-token addresses, is bounded to the existing 24,000 characters. Indivisible oversized relationships fail local preparation without truncation. Exact captured prompts/settings are reused on explicit retry. No model request runs automatically after generation or an edit.

Flash / Medium, the generation adapter, all eleven frozen constants and `prompt-baseline.json` remain unchanged. The visible footer and private reports identify version 16.4. Findings and review decisions remain advisory and do not change note text, selection, export eligibility or deduplication.

## Evidence and limits

The supplied v16.3 reports recorded valid JSON for all 72 attempted groups, with eight validation failures and no recorded transport failure or truncation. These observations do not establish a timeout or chunk-ceiling cause. The new addressing contract targets future copying failures; it does not silently reinterpret old malformed UUIDs.

The inventory is generated within the audit request under source-first instructions, not by a separately blinded model pass. Token accounting is deterministic; target selection, full-proposition support and recall equivalence remain model judgments. A wrong context classification or overly broad target can still pass structural accounting. Literal candidate matching can miss paraphrases, capitalization changes and unreliable/unmapped notes, and cannot establish absence across the deck. It does not substitute for human source review.

No live Gemini calls or native Anki import/review were performed. The new audit's completion rate, semantic quality, latency and quota cost need a separately authorized measurement. The added addressing increases planned requests for the supplied decks and can increase audit time and cost. Private reports, decks, source material, browser captures and measurement artifacts remain in ignored `scratch/anki-v16.4/`; none are added to the repository changes.
