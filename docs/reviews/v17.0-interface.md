# v17.0 interface overhaul — verification record, 2026-09-19

A presentation-layer release. The shell, the workspace composition of all six tools, the type
hierarchy, the control system and the responsive behaviour were rebuilt. No study logic, prompt,
validation tier, storage key or export format changed.

- Canonical application: `Nursing-Study-Suite v17.0.html` — SHA-256
  `b09677fcaa99f02967110a179f02710e098626781a6aa6d856a76a2881300199`, 891,279 bytes, LF-only.
  The release asset `Nursing-Study-Suite.v17.0.html` is these same bytes under the dot-separated
  download name; `scratch/release-v17.0/package.js` asserts the equality rather than transforming
  anything. Machine-readable checks: [v17.0-release-checks.json](v17.0-release-checks.json).
- Predecessor: `Nursing-Study-Suite v16.9.html` — SHA-256
  `f9e7bbbfb75175f84ceeb5f924dad34b395428ac68f6870f483f2e750234cd55`.

## What changed structurally

| Layer | v16.9 | v17.0 |
| --- | --- | --- |
| Shell | `.suite-shell` = 204px icon+label nav ▸ **permanent 292px settings column** ▸ scrolling main | `.app` grid = 244px workflow rail ▸ workspace. Settings is a dismissable right-hand drawer. |
| Navigation | Flat list of six buttons | Three named stages (Source / Plan / Practice), numbered `01`–`06`, each with its role in one line. Extraction and generation stay separate entries. |
| Header | ~120px block with a fixed "Your study workspace" title | One compact band: stage eyebrow, the active tool's name in the display face, its one-line purpose, and live chips for Knowledge Base size, browser-save state and API-key state. |
| Tool body | One vertical stack: settings ▸ more settings ▸ progress ▸ output box | `Workbench`: a 372px setup column (numbered required steps, collapsible secondary configuration, run action beneath) beside a substantially larger results surface that scrolls independently. |
| Empty screens | A centred glyph and a sentence, or a large empty output panel | `EmptyState` per tool: what this tool is for, plus the three numbered actions that produce a result. |
| Type | One sans family, sizes by pixel value | Named roles (`--t-micro` … `--t-display`); Playfair Display carries the brand, tool titles, results headlines and tier titles; JetBrains Mono carries identifiers, counts and logs. |
| Colour | Blue accent with orange used loosely | Blue = navigation, selection, structure. Orange = the accent and the one important action per stage, plus Tier 1, which already meant "highest priority". Orange never paints a status surface, so amber/red/green keep their meanings. |
| Breakpoints | 1250 / 1100 / 800 / 520, squeezing the same three-column shell | 1340 (tighten), 1080 (rail becomes a labelled top strip; the bench stacks; the run action leaves the sticky position so it cannot cover content), 720 (single column, 44px touch targets, 16px inputs). |

Six inline-styled "card" wrappers per tool were replaced by `Step`, `Disclose`, `Panel`,
`ResultsHead`, `EmptyState` and `RunStatus`. Legacy CSS variable names are retained as aliases
pointing at the new tokens, because several hundred inline styles inside the tools resolve through
them; re-pointing the aliases moved the whole application at once rather than leaving a layer of
overrides on top of the old sheet.

## What was deliberately preserved

Verified by the repository gates rather than asserted: the eleven frozen prompts and their baseline
hashes, `CARD_TRANSCRIBE_PROMPT`, extraction/generation/audit logic, LATTE buckets, tiers, fact IDs,
citations, provenance and verification semantics, Anki cloze handling, deduplication and the
three-field export, import/export compatibility, IndexedDB/localStorage keys and the recovery flow,
model routing and the Auto-profile table, cancellation, streaming and per-tool crash isolation. All
six tools remain mounted, so switching tools still preserves running work, results and unsaved
edits — asserted by the acceptance run, which edits a note, changes tool four times and reads the
edit back.

## Three findings during acceptance, all fixed

1. **The settings drawer's scrim blocked the workspace.** The first drawer implementation rendered a
   full-page scrim, which intercepted pointer events on the rail while settings was open — a drawer
   described as non-modal behaving as a modal one. The scrim was removed; the drawer now closes on
   Escape or its named close button, takes focus on open and restores focus to its trigger.
   `tools/visual-browser-tests.js` caught this.
2. **Run logs were hidden behind a closed disclosure, including failures.** Moving the run log into
   a collapsed `Disclose` also hid the "repair failed … (original kept)" line.
   `tools/remediation-worksheet-browser-tests.js` caught it. Each of the four typed run logs now
   opens itself when it holds an `err` entry, and its closed summary counts those errors.
3. **The narrow-width tool strip overlapped its own labels.** Below 1080px each stage group is a
   flex item of the scrolling rail. With the default `flex: 0 1 auto` a group's box shrank below its
   content while its children refused to shrink, so at 390px the "Plan" group was laid out 23px on
   top of the "Knowledge Base" label. The scrolling container hid this from the overflow assertion.
   Fixed with `flex: 0 0 auto`, and `tools/visual-browser-tests.js` now measures the six rail item
   boxes at every width and fails on any pairwise overlap, so it cannot come back silently.

Also fixed in passing: the two Knowledge Base view buttons printed raw backslash-u escape sequences
because the escapes sat in JSX *text*, where they are literal characters. Present in v16.9 and
earlier.

## Not tested

- **Live material.** No Gemini call was made. `neia-retest.js` and `davis-transcribe-test.js` were
  not run; they consume quota and need explicit per-run authorization.
- **Real sources.** No PDF, PPTX or card photograph was processed. Source intake, transcription
  review and the extraction diagnostics panel were exercised only through the synthetic fixture and
  by reading the shipped bytes.
- **Native Anki import and native print.** The `.txt` export path and the print document were not
  opened in Anki or a print preview. The print stylesheet inside `buildPrintDoc` was not touched.
- **Assistive technology.** Roles, names, states, focus order, focus visibility and Escape handling
  are asserted programmatically; no screen-reader session was run.
- **`tools/anki-source-review-browser-tests.js` fails, and already failed at v16.9.** It waits for
  the text `Suggested correction:`, which does not exist in the shipped HTML at either version
  (verified against commit `75e338d`, and by running the runner against a materialised copy of
  HEAD). It is not a repository gate and is unrelated to this release.
