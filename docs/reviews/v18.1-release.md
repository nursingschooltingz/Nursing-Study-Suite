# v18.1 release verification

Date: 2026-10-13. Release: v18.1. Prepared from the published v18.0 tree at commit `32b6195`.

## Why

The user compared a test-taking strategy handout with the suite and asked how the Priority Analyzer and the other tabs' tiers line up.
- **Priority Frameworks.** The handout's "Priority Frameworks" (ABCs, Maslow, safety, acute before chronic, unstable before stable) matched the Priority cascade almost exactly. Its one missing item was emergent > urgent. Neither question writer used those frameworks to choose keys.
- **Tiers.**
  - The KB tier, which Anki copies and Case Studies selects by, ranks exam importance.
  - The NCLEX Generator re-tiered every concept with its own trigger list, so a worksheet's tags could differ from the KB tier of the same fact.
  - Priority's tier ranks clinical urgency.

The user approved three changes: one exam tier, a shared priority order, and two small fixes. Negative stems stay prohibited because the user's exams rarely use them.

## Change

- **`NG_GROUNDING_ADAPTER`** gains one line. TIER is the KB exam tier and is copied unchanged to PART 1 and the PART 4 Tags line. A multi-row concept takes the lowest tier number. The batch mix is a target, never a reason to re-tier.
- **The generator's `buildFocusBlock`.** Outcome/point matches "get Tier 1 priority for selection; their PART 1 and Tags tier stays the supplied KB tier".
- **`PRIORITY_ORDER_RULES`** (new, declared after `CASE_QUESTION_RULES`).
  - **Content.** R1–R8 by name and order, B2 verbatim, grounding guards, and the instruction to name the deciding rule in words without values.
  - **NCLEX Generator.** The prompt is now `NCLEX_GEN_PROMPT+buildBatchBlock(...)+'\n'+PRIORITY_ORDER_RULES+'\n'+buildFocusBlock()+…`.
  - **`caseBuildPrompt`.** It interpolates the block after `${CASE_QUESTION_RULES}`.
  - **Not added to** `caseBuildRepairPrompt` or `itemBuildAuditPrompt`.
- **`paBuildSynthPrompt` B2** adds `emergent > urgent > nonurgent`.
- **Case Studies Tier 3 toggle** reads "Tier 3 background".
- **`tools/repo-checks.js`** adds `PRIORITY_ORDER_RULES` to `DOCUMENTED_PROMPTS`.
- **`Prompts.md`.**
  - The Priority and case builder copies were replaced from live bytes.
  - The NCLEX runtime assembly was updated.
  - An appendix entry was added for the new constant.

## Verification

- **`node verify-repo.js`: all gates pass.**
  - 3,763 assertions, 10 new.

  - `Prompts.md` carries live bytes for 15 constants.
  - LF and version agreement, the Babel transform, the V8 compile and the top-level boot all pass.
- **Mutation checks.** Each of these, applied to a copy of the HTML, fails at least one new assertion:
  - swapping shared rules 4 and 5;
  - renaming Priority's R8;
  - dropping "emergent" from B2;
  - removing the block from the NCLEX assembly or the case prompt;
  - deleting the adapter's TIER line;
  - restoring "Tier 3 distractors".
- **Changed assertions:**
  - the adapter line count (8 → 9);
  - the case-builder compile in `case-rationale-source-tests.js`, which now passes the new constant;
  - three version literals (18.0 → 18.1).
- **Browser check.** The synthetic real-App fixture (mocked Gemini, isolated storage) was served from a scratch launcher and opened in the built-in browser.
  - The sidebar version reads 18.1.
  - The Case Studies button reads "Tier 3 background".
  - The live `caseBuildPrompt` carries the block between the anchor rule and the JSON shape.
  - A real NCLEX Generator request built by the page contained the adapter's TIER line and the block after the batch context.
- **SRI.** The eight SRI-pinned scripts and both PDF worker copies were re-hashed and match.
