# v17.9 release verification

Date: 2026-10-09. Release: v17.9. Prepared from the v17.8 tree at commit `a3f79f5`.

## Why

The user had three stand-alone Python converters, written the same day, that turn NCLEX material into Anki import files: `nclex2anki.py` (Generator worksheet or Extractor exports), `img2anki.py` (question images read by Gemini) and `extract2anki.py` (Extractor exports or Copy output). They asked for all three inside the suite as three options under one new tab called "NCLEX to Anki", without changes to any other tool, so everything is in one file.

## Change

- A seventh tool, `nclex2anki` (Practice stage), rendered by `NCLEXToAnki` with the shared Workbench, Step, Disclose, Panel, RunStatus and EmptyState primitives. The only edits outside the new section are one `TOOLS` entry and one `TOOL_COMPONENTS` entry.
- The conversion logic is a line-for-line port with each script's own prefix (`n2a`, `i2a`, `x2a`). It keeps the scripts' card HTML, tags, NeedsReview checks, warning text, Anki header (`#separator:tab` … `#guid column:4`) and GUIDs. The GUID basis uses Python's whitespace class, which includes the `\x1f` field separator, and a synchronous SHA-1, so the same question gets the same GUID from the suite and from the scripts.
- Image runs call the shared `callGemini` with `responseMimeType: application/json`, four retries, the script's thinking levels (low for reading, high for AI answers) and the Flash model from Settings. `geminiHaltsBatch` decides when a failure stops the run. A MAX_TOKENS reply is treated as a failed image, as in the script. Only images over 14 MB are resized, through the existing `cardFilePayload`.
- Transcripts are cached for the session under the script's key (`sha256 | model | prompt version`). They can be saved and reloaded, and the script's `_transcripts.json` loads too.
- `I2A_TRANSCRIBE_PROMPT` and `I2A_ANSWER_PROMPT` are byte-identical to the script's `TRANSCRIBE_PROMPT` and `ANSWER_PROMPT` (checked against `img2anki.py`). They are not frozen and are now listed in the generated Prompts.md appendix (`DOCUMENTED_PROMPTS` 12 → 14).
- Card previews pass through `DOMPurify.sanitize` with a `div`/`b`/`i`/`br` + `style` policy.

## Executed checks

- **`node verify-repo.js`:** **3,525 assertions passed, zero failed** (39 added in `tools/nclex-to-anki-tests.js`). It also checked: one canonical LF-only HTML, agreement between the filename and release comment, all eleven frozen prompt hashes unchanged, Prompts.md holding live bytes for all 14 documented constants (appendix regenerated), and the full JSX Babel transformation.
- **Updated counts:** four source-shape assertions count one use per tool. Each now expects seven: `<Workbench`, `setupLabel`/`resultsLabel`, `<EmptyState mark=`, `useCappedLog(`, and `callGemini(` call sites (13 → 14). The new tool conforms to each pattern.
- **Browser:** the suite was served from a scratch-only local server and opened in the desktop app's browser pane. The tab, its three options and the rail entry rendered. A synthetic worksheet dropped on option 1 and a synthetic Extractor .txt pasted into option 3 converted to the expected cards. Without an API key, option 2's button is disabled with a note. The console showed only Babel's existing large-file note.
- **CDN pins:** all eight script resources and both worker CDN copies were fetched and re-hashed, and all matched without edits.

## Not run

- A live image run. It spends the user's quota.
- A byte-for-byte comparison with the Python scripts' output files. Python is not installed on this machine. SHA-1 was checked against Node crypto, and the parsing paths were checked on synthetic exports shaped like the suite's own downloads.
