# v18.2 release verification

Date: 2026-10-14. Release: v18.2. Prepared from the v18.1 tree at commit `c3a129b`.

## Why

The user asked whether Argon suits the three Auto rows it runs. Checking that showed a conflict:
- **v17.13** capped Argon at 32,768 output tokens, thinking included, citing a non-streaming limit from "Argon's API guidelines" ([v17.13 record](v17.13-release.md)). The limit was never checked on a real key; that record's "Not measured" section says no live Argon request was made.
- **v17.14** placed Priority synthesis, Case Studies and the item audit on Argon on the premise that their output "stays well inside" that cap. The premise was copied into DECISIONS.md, CURRENT_STATE.md, the README and the tests without being checked again.
- **Google's Gemini API model page** for `gemini-4-argon` (read 2026-10-14) lists 65,536 as the default synchronous output limit and does not mention 32,768.

The cap had a cost. Priority synthesis has thought for 62,914 tokens in one request (v17.7), and its parts were halved on Argon only because of the cap.

## Probe

The user authorized one live call and ran it from their own terminal; the key stayed in their environment.
- **Request.** `POST v1beta/models/gemini-4-argon:generateContent` (non-streaming), `maxOutputTokens: 65536`, `thinkingLevel: low`, one-word prompt.
- **Result.** HTTP 200 (PASS). Argon accepts a 65,536 ceiling on the request type the app sends.

## Change

- `ARGON_OUTPUT_CAP` is 65,536. `geminiOutputCap` and `geminiIsArgon` are unchanged, so a model with a lower limit is a one-number edit.
- `paSynthPartChars` now returns 40,000 on Argon, because it scales by the ceiling.
- `measurementOutputCap` in `tools/repo-checks.js` follows the app.
- Comments that stated the old cap gained a `v18.2` note. Historical release comments are left as written.
- The visible version is 18.2.
- Prompts are unchanged.

## Verification

- `node verify-repo.js`: all gates pass, 3,764 assertions (1 new).
  - New: an Argon request asking for 131,072 tokens is clamped to 65,536.
  - Updated: the Argon ceiling, sent body and truncation message name 65,536, and the source must contain `ARGON_OUTPUT_CAP=65536`.
  - Updated: Priority parts are 40,000 characters on Argon, and the resolved synthesis model still drives the part limit.
  - Updated: the measurement plan's Argon ceiling is 65,536, and version literals read 18.2.
- **Prompt bytes.** The 11 frozen prompt hashes match; `prompt-baseline.json` is unchanged. `Prompts.md` was regenerated for v18.2.
- **SRI.** The eight SRI-pinned scripts and both PDF worker copies were re-hashed and match.

## Not measured

- No Argon run has yet used more than 32,768 tokens in the app.
- Priority synthesis stays at medium. Whether high now fits is unmeasured.
- Argon quality against Flash on nursing tasks remains unmeasured. Argon costs about 2.7× Flash per token at current paid rates, and thinking tokens bill as output.
