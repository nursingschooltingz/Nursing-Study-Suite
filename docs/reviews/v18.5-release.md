# v18.5 release verification

Date: 2026-10-15. Release: v18.5. Prepared from the v18.4 tree at commit `5bf22c4`.

## Why

While verifying v18.4, a dry allocation run on the user's Exam 1 Knowledge Base showed the problem. A default NCLEX Generator run (50 questions, 10 per batch, 3 facts per question: 5 batches of 30 target facts) reached only the first 20 of 145 groups. v18.3 had the same limit over conditions.

The allocator's comment says it round-robins across conditions, but every batch started again at the first group with unused facts. So a run used up the Knowledge Base from its first page onward. The user asked for this to be fixed.

## Change

- **`ngAllocateBatch(groups, usedIds, {want, perCondition, neighborCap, start})`.** The new `start` option (default 0, so the old order) makes the batch walk the groups from `start`, wrapping at the end. Out-of-range, negative and non-numeric starts are reduced to a real group.
- **`ngBatchStart(groups, b, total)`.** Returns the group holding pool fact floor((b-1)·poolSize/total). A run's batch starts are spread evenly through the pool by fact count, so long conditions are not under-sampled next to many short entries.
- **The generator passes `start: ngBatchStart(pool, b, numBatches)`.** The run log says batches start at evenly spaced points through the Knowledge Base.
- **Unchanged:**
  - a batch's shape (up to 4 target facts per group, up to 2 same-group context facts);
  - per-run disjointness, and the reserve-before-call rule;
  - the box/table-first order within a group;
  - the frozen prompts.

## Verification

- `node verify-repo.js`: all gates pass, **3,830 assertions (12 new)** in `tools/v18-5-allocation-tests.js`.
- **Mutation check.** Removing the walk order, zeroing the starts, or dropping `start` at the call site each fails the module.
- **Prompt bytes.** All 11 frozen hashes are unchanged; `Prompts.md` was regenerated.
- **SRI.** The eight SRI-pinned scripts and both PDF worker copies were re-hashed and match.
- **Exam 1 KB, dry allocation** with the shipped functions (931 facts in 145 groups; no API call):

| Run | Groups reached (v18.4 → v18.5) | Entry groups | Groups per fifth of the KB (v18.5) | Mannitol targeted |
|---|---|---|---|---|
| 50 questions | 20 → 45 | 0 → 12 | 17 / 16 / 2 / 9 / 1 | no → batch 5 |
| 100 questions | 35 → 92 | 0 → 37 | 28 / 26 / 15 / 14 / 9 | no → batch 9 |

Notes on the table:
- Spacing by fact count gives the long conditions at the front of the KB more batches than the short entries after them. The third and fifth fifths are mostly short entries.
- A run long enough allocates all 931 facts, none twice.

## Not measured

- No live NCLEX run.
- Batches that start among short entries (a drug's class, mechanism, indications) give the model less same-topic material per batch than a condition does. Whether those questions read as well is unmeasured.
- A 50-question run still cannot reach every group; the condition filter remains the way to guarantee a topic.
