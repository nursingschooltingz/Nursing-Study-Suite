# v20.1 release verification

Date: 2026-11-12. Release: v20.1. Prepared from the v20.0 tree at commit `4e4b464`.

## Why

v20.1 expands **06 · Clinical Case Study Generator** so nursing students can generate multiple unfolding case studies sequentially in a single walk-away batch run and print or export multiple cases together as a single clean Exam Booklet without overwriting earlier runs.

## Change

- **Session Case Packet tray & 1-click Booklet / Paired printing (`caseSplitMarkdown`, `casePacketToMarkdown`, `casePacketJsonExport`, `CaseStudyGenerator`):**
  - Retains every generated case in an ordered session **Case Packet** tray with pill switching (`CaseRenderer` keyed on `activePacketId` so revealed answers do not bleed across cases), per-case removal, and **Clear packet**.
  - Splits `caseToMarkdown` at its `\n<div class="pagebreak"></div>\n\n` boundary to support 1-click multi-case exports (`🖨 Packet PDF (N)`, `⬇ Packet .md`, `⬇ Packet .json`) in **Booklet (Worksheets → Keys)** order (default: all clean student worksheets `1..N` first with `[fact-*]` omitted on PDF, followed by all Answer Keys, Clinical Debriefs, and Review Appendices `1..N` at the back) or **Paired (Case → Key)** order.
  - Stamps unverified cases (`error` findings) at the packet header, table of contents, worksheet, and answer key, and preserves per-case earlier-KB disclosures (`v15.17`).
- **Walk-Away Sequential Batch Queue (`caseBuildBatchTargets`, `caseRunBatchQueue`, `MAX_CASE_BATCH = 8`, `CaseStudyGenerator.runBatch`):**
  - Adds a `Select ≥8 facts` quick-pick button inside **Mix specific conditions**, a **Multi-entry run mode** toggle (**`Combine into 1 mixed case`** vs. **`Batch Queue: separate cases`**), and a **Batch queue grouping** toggle (**`1 standalone case per entry`** vs. **`1 mixed case per concept`**).
  - Enforces `MAX_CASE_BATCH = 8`, skips 0-fact entries cleanly without wasting a batch slot, displays upfront estimated API call counts and `<RunStatus label="Case study batch" .../>`, executes each queued target sequentially through `CaseStudyGenerator.run` via `batchOverrideRef` (reusing deterministic grounding validation, Fisher–Yates option shuffling, NEIA MCQ audit pool, 1-round repair, and Fact Inspector registration), and halts remaining items on Cancel or API quota exhaustion while keeping completed cases `1..k` in `casePacket`.
- **Unchanged:**
  - All 11 frozen prompt constants and `prompt-baseline.json` are byte-identical.
