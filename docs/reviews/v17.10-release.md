# v17.10 release verification

Date: 2026-10-09. Release: v17.10. Prepared from the v17.9 tree at commit `c81eec8`.

## Why

The user asked for the NCLEX to Anki tab to read PDFs in its two text converters (the worksheet converter and the Extractor converter), not the image converter. The PDFs in question are the NCLEX Generator's and NCLEX Extractor's own 🖨 PDF exports.

## Finding

Those PDFs are browser prints of Markdown rendered by `buildPrintDoc`. Reading them with the suite's own `pdfWalkPages` showed what the converters would receive:

- A Generator question's choices, and every "Why X is" / Strategy / Tags line of its answer, run together into one wrapped paragraph. Ordering steps (`___ step`), calculation blanks and worked math do the same.
- In an Extractor PDF, question numbers, numbered choices and numbered rationales all print as `N.` at a line start.
- With the browser's "Headers and footers" on, each page also carries a date/title line and a URL/page-number line.

The text alone cannot be split back reliably. The geometry can. In Chrome's print of the suite's stylesheet:

- Paragraphs start at the body's left edge, list markers about 6pt in, and wrapped list text about 17pt in.
- Wrapped lines are about 15pt apart, list items about 17pt, and paragraphs 19pt or more.
- The browser header and footer sit outside the body margin in an 8pt font.

## Change

- **Reading the page:** `n2aPdfPageLines` turns one page's pdf.js text items into positioned lines, with the same spacing rule as `pdfLayoutText`. `n2aReadPdfPages` collects them through `pdfWalkPages` and releases the document with `destroyPdfDoc`.
- **Rebuilding blocks:** `n2aPdfBlocks` drops the browser header and footer and rebuilds paragraphs, list items and headings from outdents, font size and gaps wider than the measured line pitch. A paragraph split by a page break is carried over when the new page opens mid-sentence at the same indent.
- **Generator PDFs:** `n2aPdfToWorksheetText` rebuilds the worksheet's line shape. It puts back the ANSWER line, a line per Why/Strategy/Tip/CJ/Tags/Rationale/Conditions label, numbered ordering steps, `___` step lines, the `Answer: ___ unit` blank and the worked calculation after the answer value. Worksheet questions and key entries are each one list item, so indentation is not used there; a two-digit list number moves its marker left of a one-digit one.
- **Extractor PDFs:** `x2aPdfToExportText` rebuilds the Extractor's own .txt layout. Question and answer numbers are the only numbered paragraphs at the left margin. A paragraph that is only a list of choices is split one choice per line. An Extractor PDF given to the worksheet converter takes this path too, since that converter reads the .txt layout.
- **Unchanged:** `n2aConvertText` and `x2aConvertText`, so every NeedsReview check applies.
- **New warnings:** a question count that differs from the PDF's own "N questions" line, a PDF with no text layer, and a Generator PDF given to the Extractor option.

## Executed checks

- **`node verify-repo.js`:** **3,541 assertions passed, zero failed** (16 added). It also checked: one canonical LF-only HTML, agreement between the filename and release comment, all eleven frozen prompt hashes unchanged, Prompts.md holding live bytes for all 14 documented constants (header regenerated), and the full JSX Babel transformation.
- **Oracle comparison in the real app.** Synthetic exports were built in the browser with the suite's own export code, turned into print HTML with `buildPrintDoc`, and printed by headless Chrome with and without the header and footer:
  - a 4-question and a 12-question Generator worksheet: MCQ, SATA, ordering, calculation with a lab list, and a FAILED VALIDATION stamp;
  - a 2-question and a 10-question Extractor export: numbered and inline choices, per-choice and per-option rationales, a status line, tips, strategy, CJ and conditions, with long paragraphs that cross pages.

  Each PDF was converted and compared card by card with its .md source: front, back, tags and GUID.
  - All Extractor PDFs (both options) and both 12-question worksheet PDFs matched exactly.
  - The 4-question worksheet differed only on Q4's front, where a two-item lab list in the stem shows on one line. The PDF does not record that line break.
- **Regression fixture:** `tools/fixtures/nclex-to-anki-pdf.json` keeps the line geometry of five of those PDFs and their .md sources. Mutating the label split, both header/footer rules, the choice-line split, ordering-step recovery or the two-digit header path each fails at least three assertions; removing one header/footer rule alone does not, because the other still applies.
- **UI:** with PDFs dropped in, both options produced the full card set and the download. The console showed only Babel's existing large-file note.
- **CDN pins:** all eight script resources and both worker CDN copies were fetched and re-hashed, and all matched without edits.

## Not run

- PDFs printed by Safari, Firefox or Edge. The rules are relative to each document's own geometry, but only Chrome output was measured.
- The user's own exported PDFs.
