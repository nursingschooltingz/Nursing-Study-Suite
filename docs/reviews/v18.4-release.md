# v18.4 release verification

Date: 2026-10-15. Release: v18.4. Prepared from the v18.3 tree at commit `851453e`.

## Why

The user supplied a brief from an audit of a real Exam 1 Knowledge Base against the instructor's official exam review, along with the KB (`Exam1_KB.json`, schema 1.1, 650 condition facts) and the 197-page source PDF. The audit found three defects:
- medication, diagnostic and scoring-tool content never reached a downstream tool;
- facts had no box or table provenance;
- 30,000-character chunks left content for the audit to recover in nearly every chunk.

The brief was written against v17.9 and ships as v18.4. Course material stayed on the user's machine. The KB and PDF were read locally and are not in the repository. No Gemini call was made.

## Step 0: extraction diagnostic (before any code change)

Method: `pdfLayoutText` sliced verbatim from the shipped HTML, run in Node over pdf.js 3.11.174 (the app's pinned version), with pages built the way `kbSourceUnits` builds them (`--- PAGE N ---` markers). Per-page characters are measured as `kbTextQuality` measures them.

**Text layer.** 197 pages, 422,717 characters. Characters per page: minimum 16, median 1,940, maximum 6,416. 31 pages are under 800 characters:
- part openers;
- concept maps and anatomy figures (pages 24, 30, 143, 152, 163, 164);
- short box continuations (page 45);
- the cover list (page 1).

The app's composition probe found no page where an image replaces text. The PDF holds Giddens 3e Concepts 10–13 and Saunders 9e chapters 8–10.

| Search (case-insensitive, dash variants) | Extracted text | Context (paraphrased) |
|---|---|---|
| aldosterone | 2 hits, PDF pages 94, 96 | Saunders ch. 8: a cause of potassium loss (increased secretion) and of sodium loss (decreased secretion), each a lettered item in a cause list |
| oliguria / oliguric | 0 | Table 8.1 says "decreased urine output" instead |
| Box 7.1, Box 7.2, Table 6-2, Table 7.1 | 0 | This PDF has no chapter or concept 6 or 7. Its 43 labels are numbered 8.x–13.x (for example Box 11.1, Table 8.1, Box 9.6) |
| implement safety | 0 | "safety measures" occurs once, page 94 |
| risk for altered thermoregulation | 0 | "altered thermoregulation" occurs 3 times, pages 16, 21, 26 |
| mannitol / STOP-BANG / Epworth / zolpidem | pages 180, 182 / 68 / 67 / 58, 69 | present |

**Reading order.**
- A box label and its title are followed directly by its bullets, in order. A box that continues onto the next page continues after the page marker.
- Two-column tables come out row by row, left cell then right cell. Body text is not interleaved.
- Running headers carry the printed page ("CHAPTER 8 Fluids and Electrolytes 89"), so `printedPage` is visible to the model.

**Glyph loss.** In Saunders chapters 8–10, pdf.js maps some glyphs to Unicode private-use code points instead of letters:
- the letters c and o, and the fi and fl ligatures (885 such characters on 40 pages, 71–117);
- most of them sit in chapter 9's tables (pages 109–113, about 500 characters), so a cell reads "C?nfusi?n" for "Confusion".

This degrades those tables and their quotes; it does not remove them.

**Verdict.** The terms that exist in the book are in the extracted text: aldosterone (0 mentions in the KB), mannitol, STOP-BANG, Epworth and zolpidem. So their absence downstream is a model-attention or schema problem, and Steps 1–3 apply.

The instructor's labels (Box 7.1, Table 6-2 and the rest) and the terms tied to them do not exist in this PDF. Every label the PDF does contain is in its text layer. These look like content from another book or edition, not a text-layer loss; no image fallback was built. The private-use glyph mapping is a real text-layer defect on 40 pages. It was reported, not fixed (the brief excludes extractor rewrites).

## Changes

### Step 1: entries become facts

**Field survey of `Exam1_KB.json`:**
- **medications:** name, genericName, brandNames, class, classes, classification, drugClass, mechanism, mechanisms, indication, indications, routes, dosage, administrationInstructions, considerations, contraindications, blackBoxWarnings, sideEffects, adverseEffects, adverseReactions, monitoring (strings or `{parameter, frequency}`), monitoringParameters, teaching, antidote, safetyTier, aliases, sourcePointer, facts.
- **diagnostics:** name, category, type, purpose, normalRange, normalValues, normalOrTargetRange, criticalValues, criticalAlertValues, criticalFindings, indications (array or string), nursingActions, nursingActionsAndPrecautions, nursingImplications, nursingConsiderations, contraindications (always null), tier, aliases, sourcePointer, facts.
- **scoringTools:** name, purpose, components (array or string), scoringRange, interpretation, actionThresholds, clinicalUse, aliases, sourcePointer, facts.

**Mapping (`KB_ENTITY_FIELD_MAP`):**

| Fields | Bucket / factType | Notes |
|---|---|---|

| mechanism, mechanisms | BriefPatho / mechanism | |

| teaching | Educate / education | |
| purpose, components | Tests / other | |

- **Not mapped, reported.** `category` (6 entries) and `type` (6 entries) on diagnostics, such as "Vital Signs Assessment" or "Imaging". They are kept, and the import notice lists them.
- **Flat fields on entries that already had facts.** `medications.classes` (1) and `diagnostics.category` (1) are not converted, because the brief maps only facts-less entries.
- **Identity fields, not mapped.** name, aliases, facts, sourcePointer, sources, id, tier, safetyTier.

**Fact IDs.** Derived facts get `fact-N` IDs after the conditions' facts, not `<entry>-dN`. These places accept only `fact-N`:
- Anki's chunker (`splitOversizedConditionBlock`, `ankiChunkFactIds`) and `parseKBCoverage`;
- the NCLEX worksheet citation check (`/^fact-\d+$/`);
- `FactText`.

Each derived fact keeps `derivedFrom: {collection, field}` for provenance.

**The audit filter.**
- Pass 1 counts a missing quote and keeps the fact.
- Pass 2 discards a recovered fact whose quote is not found. It sees only the audit's `missed` list.
- Derived facts are written in `mergeLatteParts` after both passes, so neither pass sees them.
- The only place a missing quote surfaced for derived facts was a validation warning (`validateLatteKnowledgeBase`). Derived facts are now exempt from it.
- A build-handler assertion runs a flat entry through a build with an audit. The derived facts arrive with `sourceQuote: null`, while an unlocatable recovery is still discarded.

**Consumer audit:**

| Consumer | v18.3 read | v18.4 reads |
|---|---|---|
| Fact index: inspector, header fact count, artifact snapshots, NCLEX known IDs, case citation checks (`buildFactIndex`) | conditions | conditions + entries (`kbFactView` inside `buildFactIndex`) |
| Knowledge Base tab: browser list, selection, Study view and its export, validation, fact count | conditions | `kbFactView` |
| Knowledge Base bucket-gap diagnostics (`kbBucketGaps`) | conditions | conditions, unchanged (per-condition LATTE gaps do not apply to a drug or a scale) |
| Anki: usable-fact gate, packet, source snapshot, source conflicts, validation, counts | conditions | `kbFactView`; packet with box/table first |
| NCLEX Generator: allocation pool, legacy packet, log | conditions | `kbFactView` with box/table first |
| Priority Analyzer harvest (`kbForPriority`) | conditions | `kbFactView` |
| Case Studies: topic list, selected facts | conditions | `kbFactView`; an entry can be a case topic |
| Audio / podcast | not in the suite | — |

The packet builders (`kbForAnki`, `kbForNCLEX`, `ngBuildFactPool`, `kbForPriority`, `ankiSourceSnapshot`) are byte-unchanged; the approved `kbForAnki` hash pin still holds. Only the call sites pass the view.

### Step 2: box and table provenance

- **Schema 1.2.** Optional `sourceKind`, `sourceLabel` and `printedPage`. `kbCoerceProvenance` lower-cases a valid kind, reads an unknown kind as prose with a warning, and keeps only text or number labels and pages. The build keeps the fields (`mergeLatteParts`), and Import JSON now does too; before, it dropped any field outside its list. A restore keeps every saved field.
- **Prompt constants changed:** `KB_EXTRACTION_PROMPT` and `KB_VERIFY_PROMPT`, nothing else. The diff is `docs/history/KB-v18.4-box-table-provenance.diff`, and only those two baseline hashes were updated.
- **Page markers and grouping.** `--- PAGE N ---` already precedes every PDF page. Step 0 showed box and table text contiguous, so the extractor is unchanged.
- **Audit inventory.** A fact's label follows its bucket, so the audit can match labels.
- **Weighting.** `BOX_TABLE_WEIGHT = 2`. `kbFactView(kb,{boxTableFirst:true})` stably orders each group's facts by weight, at the Anki packet and NCLEX pool call sites. The selectors are unchanged.
- **Study view.** `kbProvenanceText` adds "Table 6-2 · printed p. 89" after the source pointer.

### Step 3: defaults

`KB_DEFAULT_CHUNK_CHARS = 15000`, `KB_DEFAULT_AUDIT = true`, `KB_DEFAULT_OVERLAP = 1`. Two lanes remains off. The chunk field shows an approximate page count (at about 2,000 characters a page) and the "Default lowered to 15,000 in v18.4" note. The lanes help text says two lanes offset the extra calls.

The brief asked that saved settings override the new defaults. The Knowledge Base extraction settings were never saved: they are component state that resets on every load. So no saved value exists to keep, and no assertion for it was possible without adding a settings store, which was out of scope.

## Verification

- `node verify-repo.js`: all gates pass, **3,818 assertions (49 new)**.
- **Prompt bytes.** Nine frozen hashes unchanged; the two approved hashes updated. `Prompts.md` regenerated, and section 1 carries the new prompt bytes and a note.
- **Mutation check.** Six deliberate breaks each make `tools/v18-4-kb-coverage-tests.js` fail:
  - the view dropping entries;
  - the merge skipping the normalizer;
  - import dropping provenance;
  - no box-first order;
  - derived facts flagged;
  - slug-form IDs.
- **SRI.** The eight SRI-pinned scripts and both PDF worker copies were re-hashed against their CDNs and match.
- **`Exam1_KB.json` re-imported through the shipped `kbNormalizeImported` (no API call):**
  - entries without facts 57 → 0;
  - total facts (conditions + entry arrays) 702 → 932, with 230 derived facts and 51 existing entry facts given an ID and sources; condition facts stay 650;
  - fact IDs unique, all `fact-N`; validation of the view shows 0 errors and 0 warnings.
- **Dry-built payloads, v18.3 input (conditions only) → v18.4 input (`kbFactView`):**

| Term | Anki packet | NCLEX packet | NCLEX pool | Priority packet |
|---|---|---|---|---|
| mannitol | 0 → 8 | 0 → 18 | 0 → 7 | 0 → 7 |
| STOP-BANG | 0 → 2 | 0 → 3 | 0 → 2 | 0 → 2 |
| Epworth | 0 → 3 | 0 → 3 | 0 → 2 | 0 → 2 |
| zolpidem | 0 → 4 | 0 → 6 | 0 → 3 | 0 → 3 |
| aldosterone | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 (not in the KB; needs a rebuild) |

  - The Anki packet grows from 19 to 25 chunks of 12,000 characters.
  - The NCLEX pool grows from 650 facts in 62 groups to 931 facts in 145 groups.
  - A default NCLEX Generator run (50 questions, 10 per batch, 3 facts per question) targets 150 facts from the first 20 of 145 groups and reaches no entry group. This was already true for conditions in v18.3. With the condition filter "mannitol", the pool is the 6 Mannitol facts.
- **Browser.** The synthetic real-App fixture (`tools/remediation-browser-fixture.js`) was served on loopback. A synthetic KB with flat entries and a `Table 6-2` fact was loaded through the app's import normalizer:
  - the header chip read "0 entities without facts";
  - the browser listed each entry with its kind, and selecting one kept the selection and showed its Study view;
  - the Study view showed "Table 6-2 · printed p. 89";
  - the Case Studies list offered the entries;
  - the chunk field read 15,000 with the new note;
  - no console errors besides the existing Babel size note.
