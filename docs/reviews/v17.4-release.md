# v17.4 release verification

Date: 2026-09-24. Release: v17.4. Prepared from the v17.3 tree at commit `e1f6b41`. At the time this record was written the changes were in the working tree, not yet committed or published; the README download link for v17.4 becomes valid once the release asset below is uploaded.

This release implements findings R01–R07 and R09–R12 of the [2026-09-24 production review](production-review-2026-09-24.md) and hardens R02. R08 (PDF ingestion budgets) is deferred to its own measured change. Every finding was checked against the v17.3 source before implementation; the verified findings and verdicts are in that record.

- **R01:** a Calculation answer whose rationale carries no supported equation now gets the warning "calculation answer was not independently verified", which reaches the Markdown review appendix, the JSON review block and the print export. Verified equations and wrong answers against them behave as before; nothing is promoted to an error (the bounded verifier in `DECISIONS.md` is unchanged).
- **R02:** `kbReadFallbackSnapshot` reads each browser fallback key once and returns both the parsed records and the exact bytes; the hydration effect passes those bytes to the save queue as its conflict baseline. `kbReadFallbacks` remains as a wrapper for existing callers.
- **R03:** `nclexMergePairs` unions the regex pairing and the model pairing by question number: page text and matched answers are kept, missing answers are filled, questions only the model found are appended, and a number whose two texts clearly differ is counted so the log can ask for a numbering check.
- **R04:** `geminiHaltsBatch` is the one halting rule for the Knowledge Base build (both lanes), the Priority harvest, both NCLEX extraction modes and the NCLEX generator: cancellation, a deferred retry (provider wait over a minute), a 429 after the transport's own retries, or a permanent HTTP failure stops the run and keeps what was already extracted. A stopped Knowledge Base build commits nothing, like a cancelled one, and names the chunks attempted and never sent. Content failures without an HTTP status stay per-chunk. Anki generation already stopped on its first failure and is unchanged.
- **R05:** `nclexAdmitRecord` rebuilds every extracted NCLEX record from typed, bounded fields; a non-string or blank question is rejected, object-valued text fields are dropped, and malformed records are counted and sampled on the run tracker instead of reaching the disease filter or the card renderer. `nclexRepairOptions` leaves a non-string question alone.
- **R06:** a run tracker feeds `nclexRunSummary` (complete, incomplete, failed, cancelled, stopped, or nothing extracted), shown in the results view and written into the Markdown, text, PDF and copy exports with the failed chunks or batches and any skipped records named.
- **R07:** `kbUsableFactCount` runs before the Anki deck is cleared or a packet is built; a factless Knowledge Base is refused with zero requests.
- **R09:** Priority keeps streamed synthesis text after any failure, labels it incomplete on screen, and the export notice carries the failure.
- **R10:** `paParseOverlap` accepts a zero overlap; blank or non-numeric input still restores the default.
- **R11:** the browser fixture creates its context inside its protected region and closes its loopback server even when the context fails to close.
- **R12:** the README describes fact provenance as the source file plus its page or slide range with a quote check.
- **DOMPurify 3.4.15 → 3.4.16** on both CDNs with one re-hashed integrity value (28,885 identical bytes on cdnjs and jsDelivr). The two advisories published on 2026-09-23 require the in-place sanitization mode this file never uses.

The canonical filename, release comment, `suiteVersion()`, README download link, maintainer documentation, changelog, prompt-library labels and version assertions agree on v17.4. No generation prompt bytes, model profiles, warning tiers, storage keys or export formats change. One dependency changes (DOMPurify 3.4.16).

## Limits

No live Gemini calls were made; every provider failure was synthetic (a stubbed transport in the harness, a counting fetch stub in the browser). No private course material was used. The browser checks ran on a desktop; mobile devices were not tested. The halting rule stops a run; it does not add a shared cooldown or automatic resumption, so after a provider wait the user re-runs the tool. A stopped Knowledge Base build commits nothing, matching the existing cancel policy, so its completed chunks are not retained beyond the log. R08 remains open: PDFs still have no file, page or character budget. The collision counter in split-mode pairing is a heuristic on the first forty normalized characters and is advisory only.
