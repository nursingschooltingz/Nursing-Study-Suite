# v17.11 release verification

Date: 2026-10-09. Release: v17.11. Prepared from the v17.10 tree at commit `de31b94`.

## Why

The user converted two real NCLEX Generator worksheet PDFs (Exam 1, Tier 1: 154 questions; Tier 2: 62 questions) with v17.10 and got 66 cards: 36 with no choices found, most of Tier 1's answers skipped, and 196 warnings. They placed both files in scope for diagnosis. While this was being fixed, they also asked to merge the worksheet converter and the Extractor converter into one option.

## Findings

The PDFs were read with the suite's own `pdfWalkPages` in session scratch space. Only geometry and masked text were inspected. Both copies and their extracted text were deleted afterwards, and nothing from them is in the repository.

- **Line pitch:** a few 9pt lines with 13pt spacing set the measured pitch, so every 15pt wrapped line became its own paragraph.
- **Choices:** each question's choices printed as a paragraph of their own, so the first mark sat at a line start and the rest inline. The parser's two mark pools then held no run.
- **Footer:** Tier 2's browser printed its footer at the page's left edge in body-size type ("5 of 28", a date, a `file:///` path, the print title). That defined the margin and was merged into a question.
- **Drifting numbers:** Tier 1 is a pre-v17.7 export. Numbered lines inside a question or answer printed as extra list numbers: Q102's six numbered choices printed as 103–108, and entry 72's four ordering steps as 73–76. So printed question and answer numbers drift apart, by different amounts on each side.
- **Generator slips in Tier 1 itself (pre-v17.8):**
  - four "CORRECT SEQUENCE:" / "SEQUENCE:" ordering labels, which the converter did not recognise, folding every later answer into the one before;
  - five "[not parsed — see Raw view]" placeholders;
  - four answer numbers printed twice;
  - three runs where the answers after a placeholder were filed one number late until a repeated number brought them back in step (Q6–Q10, Q110, Q128–Q130).

  The .md of this worksheet has the same slips.

## Change

- **One export option.**
  - `n2aExportKind` routes each source: the Extractor's .md bold numbers or .txt "ANSWER KEY" rules go to extract2anki's converter, everything else to nclex2anki's.
  - `n2aConvertExports` combines them. Worksheet cards keep their quote handling and each kind keeps its own GUID prefix.
  - The UI has two options, and the results list what each file was read as.
- **PDF reading.**
  - Edge-of-page browser chrome is dropped by pattern before measuring.
  - The pitch is measured on body-size lines only.
  - Numbered lines do not define the margin.
  - Choice paragraphs are split in A, B, C… sequence.
  - Text before the first question is kept, so the FAILED VALIDATION stamp still applies.
- **In-order pairing.**
  - `n2aPdfIsQuestion` treats a numbered paragraph as a question when it asks, has choices or a blank, or is followed by them; other numbered list items become numbered choices or steps.
  - Questions and labelled answer entries are numbered in order. When the two counts disagree, printed numbers are used and every card is marked NeedsReview.
- **Converter, for all inputs.**
  - Ordering labels in capitals start an entry.
  - A skipped answer number no longer hides the rest.
  - An entry printed twice uses the copy whose rationale lines fit, never a placeholder.
  - Placeholders are reported and skipped.
  - Choices are scanned with extract2anki's lookbehind mark scan.
- **Misnumbered keys.**
  - `n2aKeyFit` scores how well an entry's "Why X is" lines match choice X.
  - `n2aRealignKey` moves a placeholder-led run back one place only when some entry fits the question before it and none fits its own question better.
  - An answer whose rationales fit a neighbouring question's choices is named and marked NeedsReview.

## Executed checks

- **`node verify-repo.js`:** **3,555 assertions passed, zero failed** (14 added). It also checked: one canonical LF-only HTML, agreement between the filename and release comment, all eleven frozen prompt hashes unchanged, Prompts.md holding live bytes for all 14 documented constants (header regenerated), and the full JSX Babel transformation.
- **The user's two PDFs through the merged UI.**
  - Tier 1: 153 cards; Q21 is skipped because its worksheet entry is a placeholder.
  - Tier 2: 62 cards, all NeedsReview because of the file's own FAILED VALIDATION stamp.
  - No question is left without choices.
- **Pairing audit on Tier 1:**
  - Mean rationale-to-choice fit is 86%; Tier 2's is 88%.
  - A deliberate one-position mispairing scores 24–27%.
  - No question's rationale lines fit a neighbouring answer better than its own.
- **Regression:** every earlier synthetic fixture PDF still gives the same cards as its .md source.
  - A new synthetic fixture, `old-hf.pdf`, is printed the pre-v17.7 way. Its numbered choices print as 3–7 and its ordering steps as 4–7, with the last answer printed as 8. It gives the same cards as its correctly numbered source.
  - Other synthetic cases: another browser's left-edge footer, a 9pt note, three-digit list numbers, the Generator numbering slip with and without supporting evidence, a swapped pair of answers, a placeholder duplicate, a skipped answer number, and mixed Generator/Extractor input.
- **Mutation check:** breaking any of these fails at least one assertion: the edge footer strip, the body-only pitch, the margin rule, question detection, in-order pairing, the ordering labels, the gap-tolerant key, realignment, placeholder-copy avoidance, the neighbour check, the lookbehind option scan, merged routing.
- **CDN pins:** all eight script resources and both worker CDN copies were fetched and re-hashed, and all matched without edits.

## Not run

- A byte comparison against the .md exports of the user's two worksheets. They were not available.
