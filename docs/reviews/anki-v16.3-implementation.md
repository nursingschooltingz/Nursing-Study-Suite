# Anki v16.3 implementation and verification

Date: 2026-09-13. Scope: the user-approved follow-up audit/review changes and version correction, followed by explicit authorization to commit and publish v16.3 as a new release. The release asset is `Nursing-Study-Suite.v16.3.html`, identical to the canonical repository HTML.

## Implemented behavior

- Audit parsing preserves exact source citations first. Unique whitespace differences can be mapped back to original source offsets. Initial-case recovery is restricted to an explicit small prose-word allowlist at the beginning of a fact, including the observed case-only failure; all other case differences remain strict. Canonicalized receipts retain the original span, exact returned path, source/note identities and recovery method. The provider's original response is unchanged. Inserted words, unknown IDs, numbers, comparator changes and unit-case changes still fail the entire group.
- Every validation failure names its group and JSON path; citation failures include the affected note, fact and returned span. Invalid or truncated responses are quarantined while independent groups continue. Transport errors stop the session. Retry / resume is explicit and uses captured request strings/settings for groups without accepted results. Accepted results, raw attempts, unresolved failures, failure history and session timestamps survive retries, cancellation and source invalidation.
- Advisory local checks detect equivalent numeric ranges exposed on a front, source numbers absent from the cited hidden answers, scripts absent from reliable linked source context, and suspect proposed edits. The number check is deliberately limited: matching numbers cannot establish units, roles or semantic entailment, and contextual numbers can legitimately remain visible.
- The review queue combines accepted findings and target receipts with current local warnings. It exposes captured source facts even when no note exists for a missing-target finding. Users can reference another eligible kept note, mark intentional context, or record a manual fix. Decisions never change cards, kept choices or export eligibility. Relevant changes invalidate decisions; exports preserve history and mark superseded/outdated records. A report cannot adopt current decisions from a later prepared audit during asynchronous hashing.
- Dynamic checker instructions constrain suggested edits to three distinct cloze indices, separate additional independent targets, avoid answer-bearing hints, and preserve selected higher-priority coverage when proposing duplicate removal. [Exact dynamic builder diff](../history/ANKI-v16.3-audit-builder.diff). The generation adapter, all eleven frozen prompts and baseline are unchanged. Anki remains Flash / Medium.
- The canonical file is `Nursing-Study-Suite v16.3.html`. The sidebar and private reports share `suiteVersion()`, correcting the old sidebar's 16.1 label. Report schema 3 adds pending/failed group IDs, recovery counts and explicit attempt/session/decision history.

## Verification

- `node verify-repo.js`: **1,969 assertions passed**, including live-extracted citation recovery, lifecycle, recall/suggestion and review-decision regressions; full JSX Babel transform, generated prompt documentation, LF/version checks and all eleven frozen prompt hashes pass.
- All eight script CDN resources and both PDF worker copies were fetched and match their existing SHA-384 integrity pins. No runtime dependency or pin changes were needed.
- Offline replay of the supplied failed reports accepted all 19 retained OB responses, recording one case-only recovery, while the Mental response remained rejected at the exact inserted-text citation. Input files remained unchanged. This replay does not supply the OB requests that were never attempted.
- Offline warning checks against the four supplied exports reproduced the intended exposed-range, suspect numeric-receipt, invalid-cloze suggestion, bundle-growth and priority-loss notices. Review also found a numeric slash-spacing false positive; the final implementation treats equivalent numeric slash spacing alike while preserving the slash. Detailed course-material evidence stays in ignored scratch files.
- Isolated Chrome acceptance passes with synthetic packets and mocked Gemini: a rejected middle group does not stop later groups, only the rejected group is retried, accepted results/raw attempts/captured prompts remain intact, source-only findings expose captured facts, decisions become outdated after source-link edits, and export bytes stay unchanged. Active decision and partial-result panels fit a 360-pixel viewport. No page errors or unexpected requests occurred.
- The actual App visibly displays **Version 16.3** at 1440 pixels. At 360 pixels the same text is in the DOM and the existing responsive design hides the footer; there is no horizontal overflow or application error. Screenshots and the captured file hash are saved privately with the browser evidence.

## Limits

No new live Gemini calls were made. These checks measure application behavior and replay previously supplied responses; they do not establish improved generation accuracy, exhaustive target coverage or a clinical validation pass. No native Anki import/review was performed. Visible-only and Extra-only items remain advisory because either can be context or a recall gap, depending on other kept notes and the source. The source checker still sees bounded groups, not necessarily every semantically equivalent note elsewhere in the deck.

Private verification artifacts are under ignored `scratch/anki-v16.3/`. No knowledge base, generated deck, source report or API credential is included in the repository changes.
