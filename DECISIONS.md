# Deliberate project decisions

Read this before changing application behavior, API usage, validation severity, security boundaries, or architecture. These choices can resemble bugs during a quick review, but each is intentional.

- **`SAFETY_SETTINGS` all `BLOCK_NONE`.** Nursing content includes overdose thresholds, self-harm risk assessment, and abuse/neglect scenarios that generic filters can falsely block.
- **API key in client-side `sessionStorage`.** This is a local bring-your-own-key application, not a hosted service. `#suite-api-key` sets password-manager ignore attributes (`data-1p-ignore`, `data-lpignore`, `data-form-type="other"`) and exposes an explicit **Clear** button, `exportAsPdf` clears cloned `sessionStorage` on child `about:blank` print windows immediately (`win.sessionStorage?.clear()`), and `redactApiSecrets` scrubs echoed API keys and `AIza…` tokens from provider errors and `onMeta` diagnostics before display or export.
- **`thinkingLevel` is lowercase.** That matches the Gemini REST request format used by this application.
- **Pass-1 and pass-2 quote policy is asymmetric.** Primary extraction keeps facts whose `sourceQuote` fails verification and counts the miss; the omission-audit pass discards them. The risk profiles are intentionally inverted.
- **Quote location is bounded evidence, not entailment.** The approved 2026-09-18 integrity implementation rejects adjacent-digit partial matches in both plain and de-hyphenated paths (`60` inside `600`). Since v17.15 a quote that starts or ends at a decimal point between digits is a partial number too (`5 mg` inside `0.5 mg`, `dose is 2` inside `2.5 g`), read from a decimal-marked twin of the normalized source; quotes are still matched on the unchanged normalization, so an exact or PDF-spaced decimal still matches. It counts missing anchors separately from checked quotes. This narrower omission-admission rule does not promote comparator/arrow disagreements beyond WARN or establish that a located quote supports its fact. Runtime file/chunk pointers identify actual extraction inputs; model pointers remain diagnostic evidence.
- **A halted omission audit does not stop the build.** Since v17.15 a halting failure in the audit pass (quota, provider wait, refused key) stops the audit for the remaining chunks; their extracted facts are kept and the build warnings say the audit stopped. Card transcription follows the v17.4 halting rule like the other batch loops.
- **A build saves only what a restore accepts.** Since v17.15 a newly built fact with an unknown category or a non-text subtype/factType is left out of the build and named in the log and warnings, never re-filed under a guessed category; a condition whose name gives no ASCII slug gets the id `condition`.
- **Import and restore do not invent clinical metadata.** External import preserves full source strings and rejects collection-limit overflow or invalid tier/category values explicitly. Skipped unusable rows are counted. App-saved snapshots restore without import caps or fact-ID reassignment; malformed saved data stays available for export/recovery while writes are paused. An explicit recovery choice archives preserved copies before saving resumes (`kbArchiveRecovery` prunes older `latte_recovery-*` keys first, retries after evicting stale recovery archives on quota overflow, and falls back to an automatic recovery `.json` download when `localStorage` still rejects the payload so recovery resolution never deadlocks). `kbOpenDB` arms `onblocked`, `db.onversionchange` auto-close, and a `4,000 ms` watchdog timer (closing any late-opening handle) so a hung IndexedDB upgrade falls back cleanly to `localStorage` instead of stalling startup or saves.
- **Entry facts are restated, not extracted, and every tool reads them.** Since v18.4 `normalizeKbEntities` writes facts for a medication, diagnostic or scoring-tool entry that has only flat fields (class, mechanism, indications, ranges and so on), at every build, import and restore. This is the one exception to the rule above. A derived fact restates one field value under a fixed bucket and factType (`KB_ENTITY_FIELD_MAP`). It has `derived: true`, Tier 1 as the brief asked, `sourceQuote: null` and the entry's source pointer. Explicit `facts[]` on standalone entries are validated against `KB_FACT_BUCKETS` (`kbCoerceEntityBucket`, remaining reference-idempotent when already valid), and multi-chunk builds and external imports deduplicate same-slug standalone entries (`kbDedupEntities`) across `medications`, `diagnostics`, and `scoringTools` while keeping `fact-N` numbering contiguous. Fields with no mapping are kept and reported (`Object.create(null)`), never guessed. The validator does not warn a derived fact for its missing quote; the extraction of its entry grounded it.
  - **IDs.** Entry facts get `fact-N` IDs after the conditions', because Anki, the NCLEX Generator and the fact inspector accept only that form. An import numbers them after the conditions' fresh IDs; a restore keeps every saved ID and numbers only new facts.
  - **One view.** Consumers read `kbFactView`, which lists each entry with facts as a group after the conditions. The packet builders are not changed, and `kbBucketGaps` stays conditions-only.
  - **`formulas` is not normalized.** The brief named the three collections above.
- **Box and table weighting is an order, not a sampler.** Since v18.4 `BOX_TABLE_WEIGHT` (2, prose and figures 1) only orders facts within each group, stably, for the Anki packet and the NCLEX Generator pool. Neither selector changes how many facts it takes or from which group. An unknown `sourceKind` is read as prose with a warning, never a failure.
- **`generateContent`, not the Interactions API.** It remains supported and is required for the batch/caching path used here. Non-UI-streaming extraction and verification calls (`KnowledgeBaseBuilder` Pass 1 & Pass 2, `nclexCallGemini`) opt into `:streamGenerateContent?alt=sse` (`stream: true`) so SSE frames re-arm the 900s client watchdog across long reasoning turns (with JSON fallback when synthetic harnesses return plain JSON), static prompt blocks sit in `systemInstruction` or `parts[0]` ahead of per-chunk/per-image bytes for Gemini implicit prefix caching without altering any frozen prompt bytes, and network/timeout retries apply uniform `0..999 ms` jitter while honoring server `RetryInfo` floors.
- **Core non-JSX utilities run in a native `<script>` block before `<script type="text/babel" data-presets="react">`, and unvisited tabs mount lazily on first visit.** Splitting ~1,080 lines of ES2020 utilities, persistence, DOMPurify/Markdown sanitization (`ensureDomPurifyHooks` CSS property allowlist, `https?://` | `#` `href` allowlist, frozen `N2A_CARD_POLICY`), PPTX, Gemini transport, PDF.js (`pdfSafeDocParams` forcing `isEvalSupported: false`), and print/export helpers out of the in-browser Babel compilation block reduces startup transpile cost while remaining a single `.html` file; `App` mounts only `knowledge` on boot (`visitedTabs`) and keeps visited tabs mounted thereafter so running jobs and unsaved edits survive tab switches.
- **Case keyed options and unreadable units are disclosed, not gated.** Since v17.15 a value in a case's keyed option that its rationale's cited facts do not state, and a datum value whose unit the checker cannot read (pH, INR, °C, ng/mL, counts), are warnings. Promoting either to an error is an owner decision.
- **Warn-tier validators remain warnings.** Qualitative scanning, missing-field checks, terminology lint, item heuristics, and difficulty signals can false-positive. Numeric entailment is the deliberate exception once `instantiated` gave the legitimate case its own support type.
- **Anki recall labels are advisory.** A visible-only target may be tested in another note; Extra may contain either useful context or an omitted substantive target. Neither label alone creates an export gate. Manual queue decisions describe captured notes/source/tier and do not certify semantic coverage.
- **Parser ambiguity requires source review, not reconstructed prose.** Generated fragments retain physical ledger positions. An ambiguous line boundary is a structural export issue on the affected note until Text is repaired; changing tags or Extra alone cannot clear it. Existing manual Keep choices remain independent.
- **Exact merges preserve provenance and user choices.** Generation performs exact valid-note dedupe again after proven alias normalization. Source unions, original addresses and normalization history survive. Manual repairs offer an explicit exact-merge action; nonidentical notes, invalid notes and different Keep states stay separate. No fuzzy semantic merge is authorized.
- **Content edits preserve associations and request review.** Text/Extra edits retain source IDs and mark the links for manual confirmation or revision through Apply links. This is advisory; association counts never certify the edited claim. Numeric warnings inspect revealed Text, Extra and visible hints with complete sign/unit comparisons, without becoming an export gate.
- **Generated Anki tag grammar has an explicit scope.** New structured-KB notes capture `hierarchical-v1`: each tag must have nonempty `::`-separated segments. This structural contract permits Topic and custom namespaces, excludes stray bare tokens, and preserves manual Keep choices. Unscoped records retain compatibility. Canonical condition identity and mixed mappings remain advisory; source-fact counts never choose a majority condition.
- **Anki audit locations are distinct from recall.** A visible-only target can retain both Text and Extra locations; Text presence takes precedence over extra-only. Disjoint indices on the same valid note can merge with explicit diagnostics. Conflicting citation coordinates, unknown indices, invalid roles and malformed JSON remain unresolved. Context-classification and weak-evidence signals are advisory and never rewrite cards or clear coverage automatically.
- **Anki audit accounting is distinct from semantic accuracy.** Packet-local note handles and source-token ranges establish exact identity and traceability. A complete token inventory cannot prove that the checker chose the right targets or preserved meaning. Partial validated records are retained, but unresolved required records keep the group incomplete. Whole-deck literal matches are candidates for manual review, never automatic coverage or deletion decisions.
- **NEIA evidence tiers must remain honest.** `[NEIA-VALIDATED]` means the rubric states it, `[NEIA-DERIVED]` is this project's operationalization, and `[LATTE-HEURISTIC]` is an invention. Never attribute published reliability figures to this Gemini configuration.
- **Test Plan Alignment can warn but never fail.** Neither generator receives the Test Plan activity statements. A `FAIL` on that criterion is downgraded in code.
- **Exam tier and priority tier are separate axes.** Since v18.1 the Knowledge Base tier (how important a fact is for the exam) is the only tier the KB, Anki, NCLEX Generator and Case tabs use; the generator copies it instead of re-tiering. The Priority Analyzer's Tier 1/2/3 ranks clinical urgency by its rule cascade and is never written back to the KB: its output is reworded text, not per-fact data, and merging the two would lose the urgency view. The question writers share the cascade's order through `PRIORITY_ORDER_RULES`, which a harness assertion keeps identical to R1–R8 and B2. Negative stems (EXCEPT/NOT) stay prohibited; the user's exams rarely use them.
- **`itemAudit` is intentionally blind to grounding.** It sees only what the student sees. Do not pass fact IDs, source quotes, or the fact packet into it, and do not split the shared profile by generator.
- **Case option order belongs to the stored revision.** v17.1 shuffles eligible valid items once before publication/audit and only the changed item after an accepted repair. Answers and rationale citations follow option content. Ambiguous label/order references preserve original order with an advisory; no answer-position quota or new rejection tier is imposed.
- **Worksheet option order belongs to the batch.** v17.12 applies the case rule to the NCLEX Generator: lettered MCQ and SATA choices are shuffled once per batch before validation, audit and export; answers and Why lines follow the choice. Letter or position references other than a singular "option X" keep the original order with a log note. No answer-position quota or new rejection tier is imposed.
- **A run's batches are spread through the Knowledge Base by fact count.** Since v18.5 batch b of n starts allocating at the group holding pool fact floor((b-1)*poolSize/n) (`ngBatchStart`). Before, every batch began at the first group, which in practice limited a run to the opening chapters. Spacing by facts rather than by groups keeps long conditions from being under-sampled next to many one-line entries. A batch's shape is unchanged: up to 4 targets per group, then up to 2 same-group context facts. No sampling, shuffling or per-run quota was added.
- **Points and Outcomes choose facts by plain-text matching, never by the model.** Since v18.6 each Point and Outcome line picks facts that go first in one batch (`ngFocusPlan`, `ngFocusMatch`); since v20.2, when `NCLEXGenerator`'s local Points field is left blank on a Knowledge Base carrying persisted `numberedPoints`, `buildFocusBlock` and `ngFocusPlan` (`_inheritPersistedPoints`) automatically inherit those persisted Points (matching `AnkiGenerator`), and `_batchCaps` routes overflow picks away from short final batches. A line picks facts from a group whose name or alias it contains. A Point also picks facts holding more than half of its words, one of them rare in the pool. Only the facts with the most of the line's words are kept, up to the facts-per-question setting. All picks together take at most half of a run's target facts, and they count toward the 4-per-group batch limit, so the v18.5 walk keeps the rest. Additional Context stays prompt-only, and `buildFocusBlock` wording is unchanged. No model call, embedding or synonym list was added: a missed match only leaves a Point to the walk, while a match chosen by a model could not be checked. Picking a Point's facts does not make the model write a question on them.
- **Arithmetic evidence is local and bounded.** v17.1 verifies explicit quantity multiplication/division with exact decimal cross-products and matching dimensions, using supplied facts and independently validated data as operands. No unit conversion, inferred rounding, arbitrary formula interpretation or global derived-value exemption is provided. Unrecognized calculations retain source review.
- **No-op repairs retain the failed verdict.** Property ordering and repair notes cannot establish a changed item. Accepted repairs preserve id/type and the exact option label set/count, are immutable replacements with current validation findings, and remain REPAIRED rather than re-audited PASS.
- **Worksheet `DISTRIBUTION` mismatch is an error.** It means the worksheet asserted compliance it did not verify.
- **`gemini-4-hydrogen` and `gemini-4-argon` are the defaults for the two model slots, and their thinking levels are always sent.** `MODEL_SETTINGS_DEFAULTS` ships `hydrogenModel: 'gemini-4-hydrogen'` (`hydrogenLevel: 'low'`) in the first slot and `argonModel: 'gemini-4-argon'` (`argonLevel: 'high'`) in the second slot, persisted under `MODEL_SETTINGS_SCHEMA_VERSION = 2` (`saveModelSettings`) so one-time legacy slot migration runs only on pre-v2 payloads and cross-tab `storage` events stay synchronized. Hydrogen's built-in default when omitted is `high` and Argon's is `medium`, so the suite always sends explicit per-row or manual levels (`low`, `medium`, `high`, or Hydrogen-only `xhigh`), and `geminiRequest` refuses both Argon and Hydrogen requests with no level instead of letting them silently fall back. `xhigh` is enabled on Hydrogen, clamped to `high` on non-Hydrogen custom models, and refused on Argon (whose Gemini 4 specification supports `low`, `medium`, and `high` only), and default HTTP client timeout is 15 minutes (`900,000 ms`) per Google's Gemini 4 migration guidance.
- **Auto puts reasoning-heavy, bounded-output rows on Argon and high-throughput rows on Hydrogen.** Since v17.14 (v19.2 for NCLEX generation, and v20.2 for Hydrogen) the shipped profile uses Argon for Priority synthesis (medium), NCLEX generation (high), Case studies (high) and the item-quality audit (high), and Hydrogen (`m: 'hydrogen'`) for Knowledge extraction (medium), Knowledge audit (medium), card OCR (low), Priority harvest (low), Anki (medium), NCLEX extraction (medium), and Import to Gizmo (low). Saved profile rows still win over a new recommendation (the v16.2 rule); Reset to recommended adopts it. On a free-tier key (where Argon is unavailable), switch the Argon rows back to Hydrogen.
- **The output ceiling is per model, and `geminiRequest` chooses it.** Every model gets 65,536 tokens, thinking included. v17.13 gave any model ID containing "argon" 32,768, citing a non-streaming limit that was never checked. In v18.2 a live non-streaming call to `gemini-4-argon` accepted 65,536, so Argon matches Hydrogen. The per-model branch stays for any model with a lower limit. No call site sets its own. A `thinkingBudget`, a level outside `low`/`medium`/`high`/`xhigh`, or `xhigh` on Argon is refused before sending, as the HTTP 400 the API would return.
- **JSON cut off at the ceiling is a failure, not a parse.** A `responseMimeType: application/json` request that stops with `MAX_TOKENS` throws a fatal `truncated` error carrying the partial text; it is never retried and never halts a batch on its own. Knowledge Base extraction still halves and requeues the chunk, and a truncated case still lands in the invalid-response panel. Plain-text answers (Priority, Anki, NCLEX answer key) keep the partial return with a truncation warning.
